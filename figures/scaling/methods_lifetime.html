What actually works (n=200, confirmed, stable) — the wake/sleep design. Reset working-memory positions every episode: each episode "wakes" with fresh in-context memory at positions 0…T, acts, then "sleeps" — consolidating its trajectory into ΔW — so the lifetime lives in ΔW, not in a growing clock. With a lower learning rate (1e-5, to stop online drift) this is the best and most stable design: 0.747 overall, flat across all 200 episodes, and because positions never grow it never hits the RoPE ceiling — it scales to an unbounded lifetime. Capping the clock by position-compression is a close runner-up (0.733). What does NOT work: KL-distillation collapses (→0 even at lr1e-5); adding cross-episode memory to the rollout breaks the agent (15-step loops). The honest claim: a lifelong agent improves because its weights accumulate experience — refreshed working memory each "day" — not because it reads an ever-growing timestamp.

What the code review surfaced (verify before trusting / extending):
  • CCD's loss ≠ static experience tuning's loss. Static ET masks observations (LOSS_ROLES={think,act}, train_react_wm.py:33). But CCD everything consolidation trains on obs too (lr_roles={obs,think,act}, lifetime_agent.py:204). So CCD is not the exact continual analog of the static ET cell — it adds a world-model (obs) objective. This is a plausible driver of the CCD-Act collapse: act-only + obs-heavy loss, with no think tokens to anchor the policy → drift to observation-spewing.
  • Prompted vs trained use different prompt formats. Prompted baselines use ReAct-paper Action:/Observation: framing; trained cells use [obs_k]/[act_k] brackets. Cross-format comparison caveat (already noted for native-chat).
  • Continual instruction tuning supervises {act} only (lifetime_agent.py:199), not obs — unlike CCD. Consistent with "memoryless single-step", but a different mask than the row above it.
  • The open finetuned×memory block needs two small code edits before it can run: (1) an exemplar/window prefix flag in rollout_webshop.py; (2) lifetime_agent currently makes context_accum (windowed prompt) and gradient integration mutually exclusive (optim=None if integration in (frozen, context_accum), line 165) — combining "memory in context" + "memory in weights" needs that gate relaxed.
Fair-comparison budget (how many trajectories each cell sees).
  • Same data for every trained cell: all finetuned adapters see the same 3000 trajectories (identical goals across the Act and ReAct datasets — 200/200 verified). Same eval: every static cell and every lifetime run uses the same 100 held-out goals (webshop_test[0:100], same order); continual cells stream those same 100 episodes on top of the 3000-traj adapter.
  • What differs is compute, not data. Instruction tuning chops the 3000 trajectories into ~57K (obs,act) windows; experience tuning keeps 3000 whole-trajectory windows. Each adapter is trained to convergence on a shared validation set (one early-stopping rule for all), so optimizer-steps land at 120–400 and supervised tokens at 0.39–4.4M. Convergence-based stopping is the fairness criterion: each method is trained as well as that method can be on the same 3000 trajectories.
  • For "best continual learner" the init is held fixed: every continual cell starts from the same experience-tuned (3000-traj) adapter and streams the same 100 episodes, differing ONLY in the update rule — frozen · in-context windowed · in-context persistent · consolidate-full (CCD) · consolidate obs-masked · +few-shot context · +windowed context. (The earlier "continual instruction tuning" cell starts from the instruction-tuned init instead, and is labelled as such.)

6 · NEW scenario — windowed finetuning: the parallelogram (no cold-start)

The cold-start problem. Pretraining forces the model to generate a sequence's initial tokens from (near-)zero context — under causal attention token 1 sees nothing, token 2 sees one token, … This is unlike human cognition, which never generates from nothing: there is always some prior context, whether memory or a world model. The fix — a parallelogram window. Over [soft-prompt ⊕ O/A trajectory], every token is predicted from a constant-width-W context: a blue top triangle of trainable prompts (the ever-present prior context — memory / world-model, baked into the weights) plus the green bottom triangle of the real O/A trajectory. Width W = the trajectory length, so the green covers the whole real triangle (every token reaches the start) and the prompts fill the complementary top — even the first token gets a full window, so no token cold-starts. Train: distill the whole trajectory with this soft-prompt + LoRA, loss on the unmasked r/a (think/act) tokens only (obs masked); then move to the next episode (continual). Trained and deployed windowed.

Left — what pretraining does: a causal triangle where the first tokens are generated from almost nothing (t₁ from ~zero context), and t₁ becomes an attention sink. Right — our fix: a fixed-width diagonal window, with the trainable prompts (blue) covering the top triangle so t₁'s window = [prompts ⊕ t₁] — a full W — and every token sees exactly W. On Qwen3.5-9B the mask applies to the 8 softmax layers; the 24 linear-attention layers are already bounded/decaying.

⚠ Result (n=200): 0.343 — does NOT work. The parallelogram (W=2048, P=2047 trainable prompts) rises to ~0.61 then craters to ~0.10 (ep 80–120) and only partially recovers (last-third 0.33) — far below the wake/sleep full-context CE winner (0.747). Note W≥trajectory means this is not context-limited (the green covers the whole real triangle); so the failure isn't missing context — the prime suspect is the 2047 random-initialized soft-prompts destabilizing the online policy (and they make deploy ~2× slower). Takeaway for the whole thread: every attempt to restructure/bound the context — hard truncation, KL-distillation, windowed, parallelogram — underperforms or collapses; plain full-context experience-tuning with reset positions + low LR remains the robust method. Open follow-up: a small, embedding-initialized prompt block rather than 2047 random vectors.
